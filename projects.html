Generative AI Applied AI

Generative AI — Applied Concept Builds

Problem: Reading about Generative AI does not prove you can build with it. I wanted working code behind every concept instead of notes, so I built each one as a small, self-contained application.

What I Built: A progression of builds, each implementing one concept end to end: prompt engineering, model access through API keys, text generation, a working chatbot, structured JSON output for machine-readable responses, embeddings and vector representations, cosine-similarity retrieval, and a Retrieval-Augmented Generation (RAG) flow. Later builds use LangChain to orchestrate the steps and Streamlit to make them interactive. All work is version-controlled and published on GitHub.

AI / Engineering: Prompt design and iteration; consuming LLM APIs with key handling; constraining model output to a strict JSON schema so downstream code can parse it reliably; generating embeddings and comparing them with cosine similarity for semantic retrieval; assembling a retrieval pipeline that grounds responses in supplied context rather than model memory; chaining components with LangChain; building interfaces with Streamlit.

Impact: Every concept in my GenAI skill set maps to code I have actually written, and the build order shows deliberate progression from basic prompting to retrieval-grounded systems.

Tech: Python, LLM APIs, Prompt Engineering, Structured JSON Output, Embeddings & Vectors, Cosine Similarity, RAG, LangChain, Streamlit, Git & GitHub
Machine Learning Full-Stack

Smart Farming Platform — Crop Price Prediction

Problem: Farmers frequently choose crops without knowing how market prices will move, which leads to unstable income and losses when supply exceeds demand.

What I Built: A full-stack web application that uses machine learning models to predict future market prices for various crops. The platform takes in land details, resource availability, historical price trends, and market demand, then processes that data through trained models to surface the most profitable options.

AI / Engineering: The full lifecycle of an AI application in one project — collecting and preparing input data, engineering the feature set, training and applying prediction models in Python, storing and querying records in MySQL, and serving model output through a web interface where a non-technical user can act on it. The core engineering problem is the same one GenAI products face: turn raw data into a model response a user can trust and use.

Impact: Converts scattered agricultural data into clear crop recommendations, so planting decisions are driven by price trends instead of guesswork.

Tech: Python, Machine Learning, Full-Stack Web, MySQL
IoT & AI Patent & Publication

Livestock Dual Node Monitoring System

Problem: Livestock disease is often caught too late, because a farmer cannot continuously observe the health and behaviour of every animal. The result is preventable loss and reduced productivity.

What I Built: A dual-node IoT monitoring system. The first node is an ear tag with a temperature sensor and microcontroller for vital body parameters. The second is a smart collar built on an ESP32 with an accelerometer for movement, activity, and behavioural patterns. Both nodes stream data continuously to a web platform.

AI / Engineering: Distributed system design across two sensor nodes and a server; embedded firmware on the ESP32 via Arduino IDE; continuous real-time data transmission and ingestion; analytics on the incoming stream that flag abnormal temperature or inactivity as early warning signals. Designed under a hard constraint — low cost and scalable for rural deployment — which drove the hardware and architecture choices.

Impact: Turns continuous sensor data into early disease signals a farmer can act on. The work is the basis of a filed patent (Application No. 202641092055) and a published research paper.

Tech: IoT, ESP32, Temperature & Accelerometer Sensors, Arduino IDE, Real-Time Web Analytics  |  Recognition: Filed patent + published journal paper
IoT & Hardware

Smart Irrigation System (IoT + AI)

Problem: Traditional irrigation runs on fixed schedules rather than actual field conditions, so large amounts of water are wasted.

What I Built: An automatic irrigation system that integrates IoT hardware with AI-based decision-making. Soil moisture and environmental sensors feed live readings into a controller that decides when to irrigate and how much.

AI / Engineering: A closed control loop — sensor input, algorithmic decision, physical actuation — running without human intervention. Required real-time data handling, threshold and decision logic over live readings, and integration between the sensing layer and the actuation layer on embedded hardware.

Impact: Replaces schedule-based watering with data-driven control, reducing water waste and removing manual effort from the irrigation cycle.

Tech: IoT, AI/ML Decision Logic, Soil Moisture & Environmental Sensors, Arduino IDE

Student ERP System

Problem: Managing student information, academic records, and administrative tasks manually is slow, error-prone, and hard to keep consistent across departments.

What I Built: A Student ERP system that centralises and automates student-related operations, handling records, academic details, and administrative data through a structured relational database with an interface for managing and retrieving information.

AI / Engineering: Relational schema design and normalisation, query design over MySQL, and full-stack development connecting the data layer to the interface. Impact: Replaces manual record-keeping with a single source of truth, cutting repeated effort and keeping student data consistent and quickly retrievable.

Tech: Full-Stack Web, MySQL, DBMS  |  Focus: Data Modelling & Automation
